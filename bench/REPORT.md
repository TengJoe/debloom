# Debloom 0.1.1：性能与兼容性测量

测量日期：2026-10-15。此报告替代此前的语言重构收益报告，撤回“重写最多快 0.5%”和“冷启动固定节省 43ms / 32%”两项未经对照实验支持的结论。

## 方法与证据

- 环境由程序读取：**Ubuntu 26.10 / Python 3.14.8**；不是 GitHub Ubuntu 24.04 runner。
- 每项 9 次，表中为各指标分别计算的中位数；原始样本见 [benchmark.json](../docs/measurements/2026-10-15-benchmark.json)。
- 墙钟使用 `perf_counter()`；父进程 CPU 使用 `process_time()`；已等待的子进程 CPU 使用 `RUSAGE_CHILDREN`。父进程 CPU 包括其中运行的原生库代码，不等于“纯 Python CPU”。
- 子进程 CPU 不归为 I/O。各项中位数不是同一次样本的时间分解，也不要求相加等于墙钟时间。
- 预检只调用 APT `--simulate --no-remove`，未调用 pkexec 安装，未写入系统包状态。
- 默认夹具为自动构建的无维护脚本演示包，大小 490 字节。内存 SHA-256 的小包结果不能外推到大型应用加载。

## 预检与加载

单位：ms。

| 阶段 | 墙钟 | 父进程 CPU | 子进程 CPU |
|---|---:|---:|---:|
| APT 模拟 | 980.034 | 0.733 | 979.753 |
| 完整预检 | 969.282 | 2.532 | 967.525 |
| 加载与清理 | 17.483 | 0.748 | 17.105 |
| 演示包内存 SHA-256 | 0.001 | 0.002 | 0.000 |

这些样本中，APT 子进程主导预检墙钟耗时，父进程 CPU 较少。这支持优先测量 APT 调用次数、实际包规模和真实用户路径，而不是只优化字符串解析。它不构成语言重写收益的硬上限，也不是实际安装性能测量。

## 新进程导入

全部条件使用相同解释器、相同 `-I` 参数和相同应用搜索路径。按固定随机种子交错条件次序；每次创建新进程，但**没有清理文件系统或库缓存**。这些数据不是窗口显示完成时间。

| 条件 | 墙钟 | 计时父进程 CPU | 被测子进程 CPU |
|---|---:|---:|---:|
| 裸解释器 | 9.880 | 0.277 | 9.672 |
| 应用模块导入 | 46.253 | 0.305 | 46.062 |
| GTK / Adw / WebKit 导入 | 144.464 | 0.323 | 132.419 |
| 应用模块与 GTK 实际一起导入 | 156.608 | 0.301 | 144.566 |

直接测量组合导入，不将两个独立进程的总耗时相加。没有构建 Rust / Go 版本，因此不推算编译版启动耗时、固定节省毫秒数或收益百分比。

## 当前缓存样本兼容性

结果摘要见 [compatibility-summary.json](../docs/measurements/2026-10-15-compatibility-summary.json)。逐包原始结果保存在本地独立证据目录，未公开用户的软件包缓存清单。

| 预检结果 | 数量 |
|---|---:|
| 已安装且无需更改 | 15 |
| 有可展示的计划变更 | 27 |
| APT 预检拒绝 | 2 |
| 样本总数 | 44 |

本次 42/44 个当前缓存样本通过 load/check；有计划变更不等于真实安装成功。不能将这个便利样本比例当作 Ubuntu / Debian 全部软件的兼容率。拒绝原因按程序返回的 APT 预检错误记录，不把未执行的 root 守卫检查解释为已验证的拒绝原因。

此前 `compat_results.json` 被单包试验覆盖，无法再作为旧 43 包统计的直接证据。本报告使用新测量，不恢复或伪造丢失的旧数据。

## 安全与未测量项

保留现有 `install_guard.py`、隔离解释器模式和标准库边界。语言本身不能决定安全优劣；迁移需要重新验证源码、构建、权限、依赖、提权后哈希与事务校验。本次没有进行这类迁移。

未测量：真实 root 安装、第三方维护脚本、真实窗口 ready、内存收益、分发体积、编译版对照、其他硬件和发行版性能。没有对这些项目作收益或验收声明。

## 复现与证据保留

```bash
/usr/bin/python3 bench/benchmark.py -n 9
/usr/bin/python3 bench/benchmark.py -n 9 --package /path/to/app.deb
/usr/bin/python3 bench/compat_survey.py /var/cache/apt/archives
```

默认保存到 `bench/runs/<UTC时间>-<随机ID>/`。可用 `--output` 指定新文件；已存在文件会被拒绝覆盖。失败命令不会被当作成功的性能样本，样本记录父/子 CPU 与墙钟原始值。`bench/runs/` 不进入 Git；默认基准会自行创建临时演示包，不依赖机器私有的 audit 目录。
